# Ежемесячный итоговый отчёт

Инструмент формирует сводку коммитов, попавших в ветку `master` за указанный
месяц. Коммиты группируются по дням, внутри дня — по категориям.

Категория определяется ключом в квадратных скобках в начале сообщения коммита:
`[FIX]`, `[TWEAK]`, `[ADD]` и т.д. Соответствие «ключ → категория» задаётся в
[categories.yml](categories.yml); нераспознанные коммиты попадают в
`Прочее`. Merge-коммиты (`Merge pull request ...`, `Merge branch ...`) в отчёт
не включаются.

## Как запустить автоматически (GitHub Actions)

Workflow [.github/workflows/monthly_pr_summary.yml](../../.github/workflows/monthly_pr_summary.yml)
запускается:

- **по расписанию** — 28-го числа каждого месяца в 00:00 UTC;
- **вручную** — вкладка *Actions* → *Monthly PR summary* → *Run workflow*.
  При ручном запуске можно указать год и месяц (1–12); если оставить поля
  пустыми, возьмётся текущий месяц.

Что делает job:

1. Генерирует отчёт за месяц.
2. Загружает его как артефакт `monthly-summary` (доступен на странице запуска).
3. Коммитит файлы отчёта обратно в репозиторий в `html/changelogs/monthly/`.

> Расписание срабатывает только после того, как этот workflow попал в ветку
> `master`.

## Как запустить локально

Требуется только Python 3.9+ — внешние зависимости не нужны, запросы к API
выполняются стандартной библиотекой.

Переменные окружения:

| Переменная          | Значение                                    |
|---------------------|---------------------------------------------|
| `GITHUB_REPOSITORY` | Репозиторий в формате `owner/repo`          |
| `GITHUB_TOKEN`      | Токен с правами чтения (обязателен для приватного репозитория; для публичного можно опустить) |

Примеры:

```bash
# Текущий месяц по ветке master
GITHUB_REPOSITORY=owner/repo GITHUB_TOKEN=ghp_xxx \
python "tools/monthly_pr_summary/Итоговый отчет за месяц.py"

# Конкретный месяц и год
python "tools/monthly_pr_summary/Итоговый отчет за месяц.py" --year 2026 --month 7

# Другая ветка / каталог вывода / включая merge-коммиты
python "tools/monthly_pr_summary/Итоговый отчет за месяц.py" --branch master --output-dir html/changelogs/monthly --include-merges
```

## Выходные файлы

Пишутся в `html/changelogs/monthly/` (или каталог из `--output-dir`):

- `YYYY-MM.md` — человекочитаемая сводка: день → категория → список коммитов
  (короткий sha, заголовок, автор);
- `YYYY-MM.yml` — та же структура в YAML, используется для показа в игре.

Оба файла сохраняются в UTF-8 с BOM — кириллица корректно открывается в
Блокноте, PowerShell и большинстве редакторов.

Пример `.md`:

```markdown
# Коммиты `master` за 2026-08

Всего коммитов: 3

## 2026-08-01 (2)

### Исправления

- `aaaaaaa` — Black tiles on ship landing (@cat1)

### Доработки

- `bbbbbbb` — Change interworld color (@Ivan)
```

## Настройка категорий

Отредактируйте [categories.yml](categories.yml):

```yaml
default_category: "Прочее"   # куда попадают коммиты без известного ключа

categories:
  - key: "FIX"               # ключ из [СКОБКА] в начале сообщения коммита
    category: "Исправления"  # название категории в отчёте
```

Порядок категорий в списке задаёт порядок вывода; сопоставление
регистронезависимое.
